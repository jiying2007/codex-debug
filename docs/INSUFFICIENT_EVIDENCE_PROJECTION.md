# Insufficient-evidence projection security contract

Promotion Corpus v2 may attach at most one digest-bound insufficient-evidence evaluation variant to a unique reviewed historical transition. The variant never creates another reviewed transition for the 12-case floor.

The only supported projection is `summary-only` version 1. It is generated by the controller; corpus authors cannot supply custom model-visible text or hints. The variant must expect `insufficient`, use `patchPolicy=forbidden`, and expose no root-cause terms.

Model-visible projected evidence contains only the failure kind, run/failure/timeout counts and the reproduction-command digest. It must not contain raw stdout/stderr, source anchors, Git history, case identity, fixed SHA, ground-truth summary or ground-truth files. `includeGitHistory=false` is mandatory and a pre-model leak check fails closed.

The underlying transition is still qualified with full controller evidence: exact reviewed bad commit must reproduce and its direct-child reviewed fix must pass the same command. Ground truth remains evaluator-side only.

Projection capability is not promotion evidence by itself. The current reviewed corpus remains at 4 unique transitions and 0 insufficient variants until authentic variants are individually reviewed and added.
